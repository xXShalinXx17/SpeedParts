Guía de despliegue · PuTTY + DHCP

Manual de Despliegue en Ubuntu Server

Desde el servidor en blanco hasta la aplicación full-stack en producción, conectándote con PuTTY desde Windows y trabajando con una IP asignada por DHCP que no se modifica.

Regla de oro. La IP del servidor la gestiona el DHCP de la red y no se toca desde el servidor Ubuntu. Todo el manual se apoya en un hostname interno (por ejemplo miapp.interno.local) que resuelve siempre a la IP actual.

1. Conectarse al servidor con PuTTY

1.1 Descargar PuTTY

Descarga la suite desde putty.org. Incluye PuTTY, PuTTYgen, Pageant y pscp.

1.2 Primera conexión

  1. Abre PuTTY.
  2. En Host Name escribe el hostname interno (ej. miapp.interno.local).
  3. Puerto 22, tipo SSH.
  4. Pulsa Open y acepta el aviso de host key la primera vez.
Trucos: clic derecho pega; seleccionar con el ratón ya copia.

1.3 Guardar la sesión

Escribe un nombre en Saved Sessions (ej. mi-servidor) y pulsa Save. La próxima vez: Load → Open.

1.4 Actualizar el sistema

bash
sudo apt update
sudo apt upgrade -y
lsb_release -a

2. DHCP sin tocar la IP del servidor

No se modifica Netplan. No se pone IP estática. No se toca nada de red en el servidor. La IP la gestiona el DHCP externo.

2.1 Ver la IP actual y el hostname (solo lectura)

bash
hostname
hostname -I

2.2 Obtener la MAC para pedir la reserva DHCP

La reserva se configura en el servidor DHCP de la red, no aquí. Tu única tarea es darle la MAC al admin:

bash
ip link show | grep -A1 "state UP" | grep link/ether
Al admin le pides: "Reserva DHCP para la MAC xx:xx:xx:xx:xx:xx". Nada más.

2.3 Mientras tanto: usa el hostname

  • PuTTY: perfil guardado con el hostname.
  • Nginx: server_name miapp.interno.local;
  • Certificados TLS: CN = hostname.
  • FileZilla: hostname, no IP.

2.4 Verificar que el hostname resuelve

powershell
nslookup miapp.interno.local
ping miapp.interno.local

3. SSH y usuarios

3.1 Crear usuario de despliegue

bash
sudo adduser deploy

3.2 Generar clave con PuTTYgen

  1. Abre PuTTYgen, tipo EdDSA.
  2. Generate y mueve el ratón.
  3. Guarda la clave privada como deploy.ppk.
  4. Copia el texto de "Public key for pasting into OpenSSH".

3.3 Instalar la clave en el servidor

bash
mkdir -p ~/.ssh && chmod 700 ~/.ssh
nano ~/.ssh/authorized_keys
# Pega la clave pública (clic derecho)
chmod 600 ~/.ssh/authorized_keys

3.4 Cargar la clave en Pageant

Abre Pageant → clic derecho en el icono → Add Key → selecciona deploy.ppk.

3.5 Configurar PuTTY

En Connection → SSH → Auth → Credentials, selecciona deploy.ppk. Vuelve a Session, guarda el perfil.

4. Firewall UFW

bash
sudo apt install ufw -y
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw enable
Sin el paso de allow 22/tcp pierdes la conexión SSH al activar UFW.
bash
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 21/tcp
sudo ufw allow 40000:50000/tcp
sudo ufw status numbered

5. Nginx

bash
sudo apt install nginx -y
sudo mkdir -p /var/www/tu-app/frontend
sudo chown -R deploy:deploy /var/www/tu-app
sudo nano /etc/nginx/sites-available/tu-app
nginx
server {
    listen 80;
    server_name miapp.interno.local;

    location / {
        root /var/www/tu-app/frontend;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    location /api/java/ {
        proxy_pass http://127.0.0.1:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location /api/node/ {
        proxy_pass http://127.0.0.1:3000/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
bash
sudo ln -s /etc/nginx/sites-available/tu-app /etc/nginx/sites-enabled/
sudo rm /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl reload nginx

6. MySQL

bash
sudo apt install mysql-server -y
sudo mysql_secure_installation
sudo mysql -u root -p
sql
CREATE DATABASE tu_app_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'tu_app_user'@'localhost' IDENTIFIED BY 'contraseña-fuerte';
GRANT ALL PRIVILEGES ON tu_app_db.* TO 'tu_app_user'@'localhost';
FLUSH PRIVILEGES;
EXIT;

7. Spring Boot

bash
sudo apt install openjdk-17-jdk -y

7.1 Subir el JAR con pscp

powershell
pscp -i C:\ruta\deploy.ppk tu-app.jar deploy@miapp.interno.local:/home/deploy/

7.2 Colocarlo en su sitio

bash
sudo mkdir -p /opt/tu-app/backend /etc/tu-app
sudo mv /home/deploy/tu-app.jar /opt/tu-app/backend/
sudo chown -R deploy:deploy /opt/tu-app/backend
sudo nano /etc/tu-app/backend.env
ini
SPRING_DATASOURCE_URL=jdbc:mysql://localhost:3306/tu_app_db?useSSL=false&serverTimezone=UTC
SPRING_DATASOURCE_USERNAME=tu_app_user
SPRING_DATASOURCE_PASSWORD=contraseña-fuerte
SERVER_PORT=8080

7.3 Servicio systemd

bash
sudo nano /etc/systemd/system/tu-app-backend.service
ini
[Unit]
Description=Spring Boot Backend
After=network.target mysql.service

[Service]
Type=simple
User=deploy
WorkingDirectory=/opt/tu-app/backend
EnvironmentFile=/etc/tu-app/backend.env
ExecStart=/usr/bin/java -jar /opt/tu-app/backend/tu-app.jar
Restart=on-failure
RestartSec=5
SuccessExitStatus=143

[Install]
WantedBy=multi-user.target
bash
sudo systemctl daemon-reload
sudo systemctl enable --now tu-app-backend
sudo systemctl status tu-app-backend

8. Node.js

bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install nodejs -y
sudo npm install -g pm2
sudo mkdir -p /opt/tu-app/node
sudo chown -R deploy:deploy /opt/tu-app/node
cd /opt/tu-app/node
git clone tu-repositorio .
npm install --production
pm2 start app.js --name "tu-app-node"
pm2 save
pm2 startup

bash
npm install

rm /tmp/frontend.tar.gz
sudo systemctl reload nginx

10. FTP

bash
sudo apt install vsftpd -y
sudo cp /etc/vsftpd.conf /etc/vsftpd.conf.backup
sudo nano /etc/vsftpd.conf
ini
anonymous_enable=NO
local_enable=YES
write_enable=YES
chroot_local_user=YES
allow_writeable_chroot=YES
xferlog_enable=YES
bash
sudo adduser ftpuser
sudo usermod -s /usr/sbin/nologin ftpuser
grep nologin /etc/shells || echo "/usr/sbin/nologin" | sudo tee -a /etc/shells

sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/ssl/private/vsftpd.key \
  -out /etc/ssl/certs/vsftpd.crt \
  -subj "/CN=miapp.interno.local"

Añade al final de /etc/vsftpd.conf:

ini
ssl_enable=YES
force_local_data_ssl=YES
force_local_logins_ssl=YES
ssl_tlsv1=YES
ssl_sslv2=NO
ssl_sslv3=NO
rsa_cert_file=/etc/ssl/certs/vsftpd.crt
rsa_private_key_file=/etc/ssl/private/vsftpd.key
bash
sudo systemctl restart vsftpd
sudo systemctl enable vsftpd
